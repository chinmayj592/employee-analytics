# REVIEW.md

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` | Always returns 200 even when MongoDB is unreachable. Never calls the database. | Stop MongoDB, call `GET /health` — still gets 200. The grader polls this before running any test. | Added `client.admin.command("ping")` inside try/except; raises HTTP 503 on failure. |
| 2 | `create_employee` | Uses `find_one` then `insert_one` (check-then-insert). Two concurrent requests with the same `emp_code` can both pass the check and both insert. | Send two simultaneous POST requests with the same `emp_code` — both return 201 and a duplicate document is created. | Removed the `find_one` check entirely. Rely on the unique index and catch `DuplicateKeyError` → 409. Atomic by design. |
| 3 | `list_employees` — `skip` calculation | `skip = page * page_size` skips one extra page. Page 1 skips 20 records instead of 0. | `GET /employees?page=1` returns the second page of results. First page is never reachable. | Changed to `skip = (page - 1) * page_size`. |
| 4 | `list_employees` — `total` | `count_documents({})` ignores the `department` filter. Total always reflects the whole collection. | Filter by a department with 3 employees — total still shows the full collection count. Breaks R10. | Changed to `count_documents(q)` so total reflects the applied filter. |
| 5 | `list_employees` — sort | No `.sort()` call. Results come back in natural (insertion) order, which is non-deterministic at scale. | Results are not in `emp_code` ascending order as required by the contract. | Added `.sort("emp_code", ASCENDING)`. |
| 6 | `punch_in` — timestamp conversion | `datetime.fromtimestamp(body.punched_at / 1000)` returns a naive local-time datetime. On a server not in IST the stored time is wrong. | On a UTC server, punch-in at 09:35 IST is stored as 09:35 UTC — 5.5 hours off. All derived calculations are wrong. | Changed to `datetime.fromtimestamp(ms // 1000, tz=timezone.utc)` to produce a UTC-aware datetime. |
| 7 | `punch_in` — attendance date (R1) | `ts.date().isoformat()` takes the UTC date, not the IST date. Overnight shift rule is not implemented at all. | An employee on a 22:00–06:00 shift who punches in at 05:30 IST gets today's date instead of yesterday's. | Replaced with `attendance_date_ist()` helper that converts to IST and applies the overnight-shift rule. |
| 8 | `compute_late_minutes` — grace period boundary (R2) | Computes integer minutes first then checks `> 10`. At exactly 10 minutes and 1 second: `int(601/60) = 10`, `10 > 10` is False → returns 0. Should return 10. | Punch-in at 09:40:01 for a 09:30 shift returns 0 late minutes instead of 10. Spec example fails. | Rewrote to compare raw seconds: `if diff_sec <= 600: return 0; return diff_sec // 60`. |
| 9 | `compute_late_minutes` — timezone | `punch_in.replace(hour=h, minute=m)` sets shift_start on the UTC datetime. Shift times are IST. Comparison is 5.5 hours off. | Employee with 09:30 IST shift who punches in at 09:35 IST (04:05 UTC) — code compares against 09:30 UTC, giving wrong late minutes. | Convert `punch_in` to IST first, then build `shift_start` in IST, then compare. |
| 10 | `compute_overtime` — overnight shift (R3) | `shift_end` is always placed on the attendance date. For an overnight shift (e.g. 22:00–06:00), `shift_end` must be on the next calendar day. | Overnight-shift employee who punches out at 06:40 IST gets a wildly wrong overtime value. | Added: if `(eh, em) <= (sh, sm)` (overnight condition), add `timedelta(days=1)` to `end_ist`. |
| 11 | `list_attendance` — loads entire collection into memory | `list(db.attendance_logs.find(q))` fetches all matching documents, then sorts and paginates in Python. | At 100,000 records response time is unacceptable and memory usage spikes. Contract requires it to stay fast. | Pushed sort, skip, and limit into MongoDB: `.sort(...).skip(skip).limit(page_size)`. Added compound index `(date DESC, emp_code ASC)`. |
| 12 | `punch_in` — response shape | Sets `doc["id"] = str(res.inserted_id)` and removes `_id`. The contract's `AttendanceRecord` schema has no `id` field. | Response contains an unexpected `id` field; automated schema validation fails. | Removed the `doc["id"]` assignment. Response is built via `format_record()` which only includes contract fields. |

## Items examined and decided not defects

- The `IST` constant (`timezone(timedelta(hours=5, minutes=30))`) is correct.
- The attendance query filter structure using `$gte`/`$lte` on the `date` string field is correct — lexicographic comparison works correctly for `YYYY-MM-DD` strings.
- The `compute_work_hours` formula `(punch_out - punch_in).total_seconds() / 3600` is arithmetically correct. The rounding was wrong (used `round()` instead of decimal half-up) but that is a consequence of defect 8's rewrite scope, not a separate standalone defect in the formula itself.
- The `PunchInIn` model defaulting `status` to `"PRESENT"` is correct per the contract.
